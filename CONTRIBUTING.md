# Contributing to Altumptic Projects

Thank you for your interest in contributing to Altumptic! 🛡️

## Before You Start

1. **Read** our [Code of Conduct](CODE_OF_CONDUCT.md)
2. **Check** existing issues before opening new ones
3. **Follow** our branch protection and review process

## Development Workflow

### Branch Strategy
- `main` / `master` — protected production branch
- `develop` — integration branch (where applicable)
- `feature/*` — new features
- `fix/*` — bug fixes
- `security/*` — security patches

### Pull Request Process

1. Fork the repository
2. Create your feature branch from `main`
3. Commit with signed commits (`git commit -s` or GPG)
4. Push to your fork
5. Open a Pull Request against `main`
6. Wait for review by **@thefear078**

### Requirements

- ✅ PR review required (auto-requested from CODEOWNERS)
- ✅ All conversations must be resolved
- ✅ Linear commit history (rebase, no merge commits)
- ❌ No force pushes to protected branches
- ❌ No direct pushes to `main`

## Security

Found a vulnerability? See [SECURITY.md](SECURITY.md).
**Never** open a public issue for security bugs.
